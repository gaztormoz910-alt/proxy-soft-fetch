## 6. Что НЕ трогал и почему

| Находка | Почему оставлено |
|---|---|
| **SEC-03**: ip-api.com по HTTP | Проверил: бесплатный тариф на HTTPS отвечает **403**. Перевести нельзя без платного ключа. |
| **SEC-03**: httpbin.org по HTTP в тесте анонимности | Через HTTPS прокси устанавливает CONNECT-туннель и **не может** вставить `X-Forwarded-For`/`Via` — проверка анонимности перестанет работать по существу. Здесь HTTP обязателен. |
| **PERF-05**: пул чекера на 1000 потоков | Решено оставить как есть (вопрос 6). Изменение профиля нагрузки без замера на реальном объёме не оправдано. |
| **PERF-06**: параллельные DNSBL | Замерил: 1.95 → 0.53 с в изоляции. Но функция уже вызывается из ~1000 потоков; внутренний пул отнимает пропускную способность у внешнего. С ограниченным общим пулом пачка становится **медленнее**. Осознанно не делал. |
| **PERF-06**: общий `dns.resolver.Resolver` | 0.594 мс на вызов против 2.06 с общей работы — 0.03%. Потокобезопасность `resolve()` в dnspython не гарантирована. Не стоит риска. |
| **REL-06**: `os._exit(0)` при закрытии окна | Корректное завершение требует join потоков с таймаутом; закрытие приложения может стать заметно дольше. Изменение поведения, видимое пользователю. |
| **bad_ports** в критерии «Чистый» | Решено оставить убранным (вопрос 2). Включение изменило бы, какие прокси считаются чистыми, — это продуктовое решение, а не багфикс. |
| **COR-13**: лишний `ISO_TO_NAME` lookup в экспорте CSV | Мёртвый код без последствий (поиск всегда промахивается, возвращается фолбэк). Правится вместе с хранением ISO-кода в `checker_data` — отдельная задача. |

## 8. Рекомендации на будущее (за рамками этого прохода)

1. **Разбить `gui.py`** (5500 строк, один класс на 120 методов). Минимум — вынести
   чекер и вкладку результатов в отдельные модули. Сейчас любая правка требует
   держать в голове весь файл.
2. **Заменить IPC через `print`.** Связь backend↔GUI держится на строках-маркерах
   `[REALTIME_*]`, которые парсятся `split('|')`. Два бага из этого отчёта
   (COR-04, COR-15) — прямое следствие. Очередь объектов вместо подмены
   `sys.stdout` убирает целый класс ошибок; заодно уйдёт подмена глобального
   `sys.stdout` из рабочего потока.
3. **`logging` вместо `print`.** Уровни, файл лога, отсутствие гонок за stdout.
4. **Проверять живость источников по расписанию.** `dead_github_sources.txt`,
   `bad_dialog_sources.txt`, `stale_repos.txt` собраны вручную. Со сводкой из
   `9bf1b29` это автоматизируется: прогнать `SOURCES`, вычистить мёртвое.
5. **CI на GitHub Actions**: `pytest` + `flake8` + сканер секретов (gitleaks).
   Секрет из SEC-01 такой сканер поймал бы на первом же пуше.
6. **Вынести константы в конфиг**: список DNSBL, блоклист стран, лимиты пулов,
   таймауты. Сейчас они разбросаны по коду и продублированы.
7. **Типизация.** Аннотации есть местами; `mypy` на `fetch_proxy.py` дал бы
   быструю отдачу — там достаточно однородные структуры данных.
8. **Сообщения коммитов.** `Upgrade 1`…`Upgrade 23` не позволяют понять, что
   менялось; при разборе регрессии придётся читать диффы целиком.
